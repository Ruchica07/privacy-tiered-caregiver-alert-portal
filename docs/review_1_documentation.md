## 3. Metric Definitions & Analysis of Results

### 1. Actionability Rate: 100.0% (Target: &ge; 90.0%) — PASS
- **Definition**: Percentage of generated alerts that provide concrete, operational next steps (e.g. check front door smart lock, place routine morning check-in call) rather than alarming, non-actionable observations.
- **Measured Finding**: Every alert template generated by `engine/rules.py` couples an evidence summary with a non-clinical actionable next step.

### 2. Privacy Compliance Rate: 100.0% (Target: &ge; 95.0%) — PASS
- **Definition**: Calculated dynamically across all 164 rendered caregiver alerts. A render is classified as compliant if and only if:
  1. The rendered tier does not exceed the caregiver's consented tier for that category (`rendered_tier <= consented_tier`), AND
  2. All text fields in the rendered alert pass content linter checks with zero banned diagnostic or medical phrases.
- **Formula**: `(compliant_renders / total_filtered_renders) * 100 = (164 / 164) * 100 = 100.0%`.

### 3. Unnecessary Disclosure Rate: 0.0% (Target: &le; 5.0%) — PASS
- **Definition**: The percentage of alert renders that exposed information above the caregiver's consented tier.
- **Measured Finding**: Across 164 evaluated renders, 0 leakages occurred. The privacy filter defaults to Tier 0 fail-safe for unconfigured categories and withholds alerts entirely when consent is revoked.

### 4. Alert Delivery Accuracy: 100.0% (Target: &ge; 90.0%) — PASS
- **Definition**: Precision of the rules engine against synthetic ground-truth anomaly events ($TP / (TP + FP)$).
- **Measured Finding**: All 24 generated alerts mapped to injected ground-truth anomalies (nocturnal wandering, check-in delays, social withdrawal, sensor outages), yielding 0 false positive alert storms.

### 5. Freshness Detection Rate: 100.0% (Target: &ge; 95.0%) — PASS

### 6. Alert Recall: 100.0% (Target: &ge; 90.0%) — PASS

## 4. Professional Role Consent Constraint Verification

A critical requirement is that the **Care Coordinator / Professional role does NOT bypass older-adult consent**:

1. **Category Consent Non-Bypass**: Even though a care coordinator has a default role cap of Tier 3, if the older adult has not granted consent for a specific category (e.g., Location & Safety), the backend returns `None` (`decision: withheld`). The coordinator cannot view the alert.
2. **Tier-Level Constraint**: If the older adult grants only Tier 1 access for a category to the care coordinator, the backend strictly renders at Tier 1 (`decision: shown_downgraded`). Trend sparklines and clinical notes are redacted.
3. **Instant Revocation Effect**: If consent is revoked mid-stream, subsequent queries by the care coordinator immediately return `None`.
4. **Automated Verification**: These behaviors are formally verified in automated unit tests:
   - `test_professional_coordinator_cannot_bypass_unconsented_category`
   - `test_professional_coordinator_constrained_by_tier1_consent`
   - `test_professional_coordinator_withheld_on_revocation`
   - `test_higher_role_never_receives_unauthorized_health_info`

## 5. Operational-Support-Only Architectural Boundary

The entire portal strictly maintains an **operational-support-only** boundary:
- **No Medical Device Claims**: Persistent disclaimers displayed in the UI banner and API responses: *"Operational & Wellbeing Support Portal — Not a Medical Device or Emergency Medical Service (EMS) Dispatcher."*
- **Content Linter Enforcement**: Text passing through `engine/content_linter.py` is checked against regex dictionaries of banned medical terminology (e.g. disease names like "Alzheimer's" or "Dementia", specific medications like "Metformin" or "Donepezil", raw clinical measurements like "140/90 mmHg", and prescriptive medical advice).
- **Automated Fallback**: Any text containing prohibited medical terminology is automatically sanitized or replaced with pre-approved operational phrasing before reaching the UI.
